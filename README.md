# Lead Platform v0.2.0

Checkpoint 2 adds Firebase Authentication on top of the stable v0.1.1 foundation.

## What works in this release

- Email/password registration and sign-in
- Google sign-in
- Password reset email
- Logout
- Auth session persistence through Firebase
- Protected application shell
- FastAPI server-side verification of Firebase ID tokens
- `/api/v1/auth/me` protected identity endpoint
- Clear configuration/error states when Firebase is missing
- Existing v0.1.1 dashboard shell and health integration preserved

Lead search is still intentionally disabled. Turso is not added in this checkpoint.

## Important security boundary

The frontend uses Firebase's normal web configuration values. The Firebase **Admin service-account key is server-side only** and must never be placed in `frontend/.env`, committed to Git, or shared publicly.

## Update from v0.1.1

## 3. Configure Firebase

Follow `docs/FIREBASE_SETUP.md` exactly.

At minimum you will configure:

### Frontend `.env`

```env
VITE_API_URL=http://localhost:8000
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=...
VITE_FIREBASE_PROJECT_ID=...
VITE_FIREBASE_APP_ID=...
VITE_FIREBASE_MESSAGING_SENDER_ID=...
VITE_FIREBASE_STORAGE_BUCKET=...
```

### Backend `.env`

```env
APP_NAME=Lead Platform API
APP_VERSION=0.2.0
APP_ENV=development
CORS_ORIGINS=http://localhost:5173
LOG_LEVEL=INFO
FIREBASE_PROJECT_ID=your-project-id
FIREBASE_CREDENTIALS_PATH=D:/Secrets/lead-platform-firebase-admin.json
FIREBASE_SERVICE_ACCOUNT_JSON=
```

For local development, the credentials path method is easiest. Keep the JSON file outside the Git repository.

## 5. Expected user flow

1. Signed-out users see the Login/Register screen.
2. Create an account with email/password or use Google.
3. The frontend obtains a Firebase ID token.
4. The frontend sends that token to `GET /api/v1/auth/me`.
5. FastAPI verifies the token using Firebase Admin.
6. Only after server verification does the main application open.
7. Sign out returns to the authentication screen.

This means hiding the UI is not the security boundary; the backend independently verifies the Firebase identity.
